# Native port milestones

1. **Reference and artifacts.** The Phase II recipe and immutable upstream revision are pinned in the [reference contract](reference-contract.md). The Rust converter accepts local safetensors exports, merges the rank-256 adapters and five-channel head, and validates the complete native graph before publishing a bundle. Missing or mismatched critical tensors fail conversion. Fixed prompt embeddings avoid runtime text encoders; neither the converter nor runtime executes pickle or downloads weights. See the [artifact contract](artifacts.md) for provenance and licensing requirements.
2. **Native inference.** The complete pipeline executes on CPU, Candle Metal and Burn WGPU on the local Apple M2 Max. It preserves posterior sampling, explicit diffusion noise, mask pooling, added text/time conditioning, the five-channel UNet output, scheduler and latent alpha blending. WGPU device/operator/recovery checks have also passed. CUDA remains an optional source implementation requiring actual device acceptance.
3. **Numerical acceptance.** All 18 stages pass on CPU, Metal and WGPU for the independent 80×96 input with frozen small-case limits. An independent 640×384 CORNE-Val photo also passes all 18 stages with a separately frozen, measured full-size FP32 envelope that includes RMS caps. The earlier large-photo failures against the tighter limits are preserved. This establishes bounded case acceptance, not universal parity or image quality. See [qualification](qualification.md) and [tests/README.md](../tests/README.md).
4. **Platform and performance qualification.** macOS CPU/Metal/WGPU real-model execution and first/warm timing measurements exist. Profiling-build measurements on Candle 0.11 put the 640×384 photo at 2.76 s on Metal (11.3 GiB peak, down from 30.6 GiB), 18.2 s on WGPU and 22.0 s on portable CPU, and the 80×96 input at 1.52 s on portable CPU; the remaining gap to PyTorch MPS (0.74 s) is mostly VAE normalization, upsampling and convolution. See [performance](performance.md). Linux and Windows CPU cross-checks pass, but actual host runtime and CUDA acceptance remain open. Reduced precision, more images/resolutions and application memory admission still need qualification. CI configuration and cross compilation are not native runtime evidence; shared-host timings are preliminary observations.
5. **Application integration.** PhotoCraft's opt-in ML-service smoke has passed against the local bundle and trusted-manifest loader: odd source dimensions are restored, repeated outputs match exactly, and a held output reservation enforces Busy. This is a synthetic-crop service bridge result; native app preview/apply/undo, selection/effect-region semantics and cancellation experience remain consumer-owned gates before any automatic promotion.

No weights are embedded or redistributed by default. Each acceptance result must identify its artifacts, revisions, platform, dtype and tolerances; completing inference alone does not establish numerical parity.
